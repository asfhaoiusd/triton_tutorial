**实践中已验证的经验（请保留）：**

1. **归约维（最后一维）** 不能随意用 `program_id` 切开；要么整行装下，要么 program 内 `for` 分块合并统计量。  
2. **Online Softmax / 分块 Norm** 往往是为了 N 很大或为后续 Flash 融合；单独写完整 Softmax 时 online **不一定更快**（多读一遍）。  
3. **Naive 整行 `BLOCK_N = next_power_of_2(N)`** 在 N=8192 时会寄存器爆炸；沿 N 分块后 LN 可接近 torch 量级。  
4. 对比要公平：`input_precision` / TF32、`synchronize`、warmup。  
5. **`@triton.jit` 里不能调 Python wrapper**；组合算子在 Host 侧串调用。  
6. **3D matmul 接多头**：`(B,H,S,d)` 先展成 `(B*H,S,d)`。Flash 多头则 `grid=(B,H)`，基址加 `stride_h`。  
7. **atomic 累加 + autotune** 必须 `reset_to_zero=[...]`，否则 benchmark 污染结果。  
8. **融合**：中间结果留寄存器/SRAM，不写 HBM；`Swiglu_pro` / Flash 是正例，Host 拼 naive attn **不算** kernel 融合。  
9. **SDPA ≠ 单一 Flash**：多后端调度；对照用 `scaled_dot_product_attention`，不要用带投影的 `multi_head_attention_forward`。  
10. **FA2 是双循环**：外层 Q 行块、内层 K/V 列块。外层可映射成 `pid_m`，内层 **必须** `for`（online 统计量不能按 N 拆 program）。  
11. **Launch** = 一次 `kernel[grid](...)`。多头不要 Python `for h` 调 H 次，用 `pid_h` 一次 launch。  
12. **Causal 加在 `qk` 上**（`offs_n <= offs_m` → `-inf`），不是 `tl.load` 的越界 mask。K/V 块里常同时含过去和未来。  
13. **Head dim `D` 保持 64/128**。把 hidden=512 当一头会让 `(BLOCK_M,D)` 爆 shared memory。  
14. Autotune 若对同一输出做 `load += store`，需要 `restore_value` / 每次清零。  
15. **Backward 是 JVP，不是组 Jacobian**：上游给 `dy`，kernel 直接写出 `dx`（以及参数梯度）。  
16. **Triton kernel 不进计算图**：必须用 `torch.autograd.Function` 把 fwd/bwd 接起来；`@triton.jit` 里仍然不能调 Python wrapper。  
17. **`save_for_backward` 只存反向闭式真正用到的量**（Softmax 存 `y` 不存 `x`）；Flash 不能存完整 `P`，否则正向省下的 `O(S²)` 白做。  
18. **`Function.apply` 才建图**；自己调 `forward` 不会进 `backward`。`ctx` 是这一次 apply 的便条，不是 `self`。  
19. **`torch.autograd.grad(outputs, inputs, grad_outputs)`**：第三位才是 `dy`；`inputs` 必须 `requires_grad`。默认用完拆图，`do_bench` 不要对已 grad 过的 `y` 再求导，计时直接打 kernel。  
20. **stride = 逻辑维 +1 时内存跳几格**；offs 是坐标，地址 = `base + Σ offs_i * stride_i`。3D 张量每个只有 3 个 stride。  
21. **有 `@triton.autotune` 就不要再传 `BLOCK_*`**；`grid` 用 `lambda meta`。`tl.trans` 不是 `tl.transpose`。  
22. **参数梯度跨行归约**：`dγ/dβ` 用本 tile `sum(axis=0)` + `atomic_add` 到 `(N,)`；autotune 必须 `reset_to_zero`。  
23. **Triton 裸输出没有 `grad_fn`**：`autograd.grad(o_triton, q, do)` 走不通。对照用 `Function.apply` vs SDPA，一次 `grad(o, (q,k,v), do)`；`create_graph` 一阶用不到。  
24. **FA 存 LSE 不存 P**：`lse` 是 `(B,H,S)`，不要和 4D 的 `o` 比 shape。`P=exp(S-LSE)`。`dQ` 用 `atomic_add` 必须 `zeros_like`，`empty` 会累进垃圾。  
25. **FA bwd 的 smem 比 fwd 紧**：同时驻留 Q/K/V/O/dO/P/dS。本机上限 101376，`64×64×D=64` 要 147968 会 `OutOfResources`；`BLOCK_Br/Bc=32` 能 launch。  
26. **跑示例用 `python path.py`**，不要 bash 直接执行没 shebang / 没 `+x` 的 `.py`。

### 阶段 H — Backward（当前主线）

目标：会为已有 Triton 正向核补反向，并接到 `loss.backward()`。  
原则：**公式闭式 → 小 kernel → `autograd.Function` → 对 PyTorch 的 `autograd.grad`**。先正确，后 autotune。全程 fp32。

反向和正向是同一套 Triton 写法，多出来只有三件事：

1. **JVP，不组 Jacobian**：给 `dy`，直接算 `dx`（以及 `dw` 等）。  
2. **`torch.autograd.Function`**：Triton 核不进计算图，必须自己接 fwd/bwd。  
3. **存 vs 重算**：`save_for_backward` 只存闭式用得到的量；Flash 不能存完整 `P`。

```text
class TritonOp(torch.autograd.Function):
    @staticmethod
    def forward(ctx, *args):
        y = fwd_kernel(...)
        ctx.save_for_backward(...)   # 最小集合
        ctx.eps = ...                # 标量用 ctx 属性，不要硬塞进 saved_tensors
        return y

    @staticmethod
    def backward(ctx, dy):
        saved = ctx.saved_tensors
        return bwd_kernel(dy, *saved)   # 与 forward 参数一一对应；无梯度的位置返回 None
```

调用：`y = TritonOp.apply(...)`。校验用 `torch.autograd.grad(y, inputs, dy)`，不要只看 `allclose` 正向。

**刻意跳过：** ReLU 的 `dx = dy * (x>0)` 是纯 elementwise，学不到归约，不当主练习（10 分钟想通即可）。  
**刻意稍后：** 完整 FA backward 实现、fp16 反向、一上来 fused bwd。

#### H.1 Softmax backward ✅

**为什么先它：** Attention 反向的核心公式；你们已有整行 `naive_softmax`，归约维策略可原样复用。

**公式：** `y = softmax(x)`（最后一维）

```text
dx = y * (dy - sum(y * dy))     # sum 沿最后一维，再广播
```

`∂y_i/∂x_j = y_i (δ_ij - y_j)`，和 `dy` 收缩即上式。**反向用 `y` 不用 `x`。**

**数据流：**

```text
fwd:  load x → max → exp → sum → y = exp/sum → store y → save y
bwd:  load y, dy → s = sum(y * dy) → dx = y * (dy - s) → store dx
```

**文件：** `04_softmax/step90_backward.py`  
正向复用 `naive_softmax`（整行，`BLOCK_COLS = next_power_of_2(N)`）。

**交付：**

- [x] `softmax_backward_kernel`：一个 program 处理 `BLOCK_ROWS` 行，列维一次装整行；越界 mask；归约 `axis=1`  
- [x] `TritonSoftmax(torch.autograd.Function)`：`forward` 存 `y`；`backward` launch 反向核；返回 `(dx,)`  
- [x] 2D `(M,N)`、3D `(B,S,D)` 与 `F.softmax` 的 `autograd.grad` 对齐  
- [x] `do_bench`：正向 / 反向分别和 torch 比（反向直接打 kernel，不对已释放的图再 `grad`）  
- [x] 理解：`Function.backward` 的返回个数 = `forward` 除 `ctx` 外的参数个数

**加练（计划外，已做）：**

- [x] ReLU bwd：`dx = where(x>0, dy, 0)`，`relu_kernel.py` 内 `TritonReLU`；fp32 对齐  
- [x] LayerNorm bwd：见 H.2b（提前做了，公式含 `μ/rstd` 与 `dγ/dβ`）

#### H.2 RMSNorm backward ⬜

**为什么第二：** 多一个**参数梯度**，且 `dx` 比 Softmax 多一项「统计量对 `x` 的依赖」。

**正向（已有）：** `y = w * x * rstd`，`rstd = 1/sqrt(mean(x²)+ε)`，`w: (N,)`

**反向要出两个梯度：**

```text
# 行内：xhat = x * rstd
dw = Σ_{batch,token} (dy * xhat)          # 沿 B、M 归约，得到 (N,)
dx = rstd * (w*dy - xhat * mean(xhat * w * dy))
```

`mean` 沿最后一维。推导时把 `rstd` 看成 `x` 的函数，不要漏第二项，否则只在 `w` 为 1 且假装 `rstd` 常数时碰巧对。

**存什么：** `x, w, rstd`（`rstd` 每行一个标量，极便宜）。不要重扫算 `sum(x²)`，除非故意练重算。`eps` 放 `ctx.eps`。

**文件：** `05_norm/` RMS bwd（可跳）  
正向复用 `online_rmsnorm` 或先写整行版（N 不太大时整行更简单，对齐后再分块）。

**交付：**

- [ ] `dx` kernel：按行并行，和正向同一套 `pid_b` / `pid_m`  
- [ ] `dw`：沿行累加到 `(N,)`。教学优先「单独 reduce kernel」或 Host 上 `sum`；若用 `atomic_add`，autotune 必须 `reset_to_zero`  
- [ ] `TritonRMSNorm.apply(x, w)` 返回与 `F.rms_norm` 对齐的 `y`；`autograd.grad(y, (x,w), dy)` 两项都对  
- [ ] 形状先 `(4, 256, 512)` 或 `(8, 128, 1024)`，对照 `F.rms_norm(..., weight=w, eps=...)`

**先不做：** 和 Linear 融在一起的 fused RMSNorm bwd。LN 已提前在 H.2b 做完，本小节可跳过。

#### H.2b LayerNorm backward ✅（先于 H.2 完成）

写在 `05_norm/step01_layernorm.py` 同文件。比 RMSNorm 多中心化：

```text
xhat = (x - μ) * rstd
y    = γ * xhat + β
g    = γ * dy
dβ   = Σ_{行} dy
dγ   = Σ_{行} dy * xhat
dx   = rstd * (g - mean(g) - xhat * mean(g * xhat))
```

- [x] `dγ/dβ`：tile 内 `sum(axis=0)` + `atomic_add`；autotune `reset_to_zero=["dw_ptr","db_ptr"]`

#### H.3 Naive Attention backward（Host 链式）⬜（插队后仍建议补）

**为什么第三、且必须在 FA bwd 之前：** 先把 Attention 的梯度数据流走通，再谈「不物化 `S`」。这里**允许物化** `S/P`，用已有 3D matmul + H.1 Softmax bwd 在 Host 串起来。

**正向（已有 naive）：**

```text
S = Q @ K^T / √d
P = softmax(S)
O = P @ V
```

**反向（链式，全部 Host 组合）：**

```text
dV = P^T @ dO
dP = dO @ V^T
dS = softmax_backward(P, dP)          # 复用 H.1，输入是 y=P
dQ = dS @ K / √d
dK = dS^T @ Q / √d
```

**文件：** `06_attention/` naive attn Host 链式（尚未写）  
单头 `(B,S,D)` 即可；多头把 `B*H` 当 batch，与 `naive_multihead_attention.py` 同一套路。

- [ ] `backward` 按上面五步串 matmul + `softmax_backward`

#### H.4 读懂 FlashAttention backward 🟡（公式已落核，笔记未交）

原计划先笔记、H.3 后再写核。2026-09-11 已在多头 causal 同文件里开写 bwd（外层 KV、内层 Q、`atomic_add` 攒 dQ）。验收仍是**能讲清楚 + 数值对齐**，不只是 bench 出 ms。

**正向已省下的：** 不写 `S/P`，只写 `O`，片上留 `(m, l)`。  
**反向不能把它们再写出来。** 做法是重算换显存：

```text
存：Q, K, V, O，以及每行的 LSE（或 (m,l)）——都是 O(S·D) 或 O(S)
不存：S, P                                      —— O(S²)

对每个 Q 行块 i:
  初始化 dQ_i
  for j in K/V 列块:                 # 仍必须 kernel 内 for
      重算 S_ij = Q_i @ K_j^T / √d
      用已存 LSE 得到 P_ij = exp(S_ij - LSE_i)
      dV_j += P_ij^T @ dO_i
      dP_ij = dO_i @ V_j^T
      dS_ij = P_ij ⊙ (dP_ij - rowsum(dP_ij ⊙ P_ij))   # 即 H.1，但只在 tile 上
      dQ_i += dS_ij @ K_j
      dK_j += dS_ij^T @ Q_i
```

和正向一样：外层 Q 可映射成 `pid_m`，内层 KV **不能**按 N 拆 program。`dK/dV` 多个 Q 块会写同一块 → 需要原子或按 KV 再切一趟。

**交付（笔记即可，可写在本文件本节或 `06_attention/NOTES.md`）：**

- [ ] 默写：存什么 / 不存什么 / 为什么  
- [ ] 指出 `dS_ij` 那一行就是 H.1 的 tile 版  
- [ ] 指出 `dK/dV` 的写冲突从哪来  
- [ ] 能对照 H.3 的五步，说明每一步在 FA 里变成「tile 上重算 + 累加」

**已落核（同文件，尚未 `_check_grad`）：**

- [x] fwd 额外写 `LSE = m + log(l)`，shape `(B,H,S)`  
- [x] bwd：外 KV `BLOCK_Bc`、内 Q `BLOCK_Br`；causal `offs_c <= offs_r`；`P=exp(S-LSE)`；`Δ=sum(dO*O)`；`dV+=Pᵀ@dO`；`dS=P*(dP-Δ)`；`dQ` atomic、`dK/dV` 本地攒  
- [x] `TritonFlashAttentionCausalMHA`；Host 包装能 launch（`dq=zeros`，`32×32` 躲开 smem 上限）
